StayOS PMS Main PMS Screen (Application Shell) UI / UX Design Documentation (with AI Generation Prompt) Document Type: UI/UX Design Module: Main PMS Screen / Shell Status: Draft v1.0 1. Layout Left sidebar (persistent, dark-navy icon rail — same visual language as Configuration's shell): 11 nav items in this fixed order — Dashboard, Reservation, Front Desk, Rate & Availability, Audit, Business Channels, Guest, Housekeeping, Utility, Reports, Configuration. Each item shows an icon + label; the active route is highlighted. Top bar: property name (with a property switcher if the user has access to more than one), the current working date, a global search field, a notification bell, and a user menu (name, role, Sign Out). Main content area: renders the selected module's screens. For the 10 not-yet-built modules, shows a simple "Coming Soon" placeholder with the module name and icon rather than a blank or broken page. Configuration is visually identical to the other 10 items in the sidebar, but behaves differently on click (see Key Interactions) — the user should not be able to tell it's a separate application from the sidebar alone. 2. Key Interactions Clicking any of the 11 items — including Configuration — changes the main content area via ordinary client-side routing. No full page reload for any of them; Configuration is not special-cased at the routing level. Configuration's route mounts an entirely different layout component (its own top nav: Property/Configuration/Setting/Miscellaneous, plus an Exit Configuration action) rather than the Main PMS sidebar — but this is a layout swap within the same app, not a redirect to a different application. Clicking "Exit Configuration" inside the Configuration layout routes back to /dashboard within the same app and session. If the user's role doesn't permit a given module, that item is shown greyed out with a lock icon rather than removed entirely, so staff understand the option exists but isn't available to them. 3.
